# Требования к внешний интеграции

## Интеграция "Интеллектуальный домофон"

Сторонний партнер предоставляет систему "Интеллектуальный домофон". Созданием модели будет заниматься компания PropDevelopment и предоставлять ее партнеру. 

Для добавление нового человека в систему распознавания PropDevelopment заносит фото и данные человека в свою систему. Ему присваивается токен (GUID). Фото и токен, передается партнеру для внесения в модель. 

Если модель системы "Интеллектуальный домофон" определяет человека по фото, то на выходе получаем токен. Хеш этого токена или он сам и данные помещения, куда пытается попасть человек, передается по зашифрованному каналу в PropDevelopment. Там проверяется разрешен ему доступ в данную квартиру или нет.

Если модель не смогла определить человека, то фото в шифрованном виде и данные квартиры передается в систему PropDevelopment. Она пытается вызвать приложение собственника, что бы он принял решение о допуске человека в квартиру. Если ответа нет, то блокируется доступ.  

## Интеграция "**Интеллектуальный шлагбаум**"

Сторонний партнер предоставляет систему "Интеллектуальный шлагбаум". Созданием модели для системы будет заниматься компания PropDevelopment и предоставлять ее партнеру.

Модель на основании фото пытается расшифровать номер подъехавшего автомобиля. Если номер удается определить, то сервис партнера отправляет запрос в систему PropDevelopment, с токеном шлагбаума и шифрованным данными номера. Система PropDevelopment проверяет разрешен ли доступ данному автомобилю и дает разрешение на открытие шлагбаума. 

## Требования к безопасности

1. **Аутентификация JWT** (JSON Web Token). Все запросы от партнера и к партнеру должны содержать токен JWT для аутентификации партнера.
2. **Авторизация OAuth 2**. Для взаимодействия с API партнером применяется метод авторизации с использованием OAuth 2. Это позволит контролировать методы, которые доступны партнеру;
3. **Firewall**. Между API партнера и системой PropDevelopment дожен быть установлен  Firewall который будет разрешать доступ только на выделенные порты, осуществлять фильтрацию трафика и экранировать систему PropDevelopment в закрытый сегмент; 
4. **Шифрование трафика**. Весь трафик между системой PropDevelopment и API партнеров должен идти по протоколу HTTPS с использованием TLS‑зашифрованного соединения. Сертификаты HTTPS должны выпускаться PropDevelopment или доверенными центрами.
5. **Токенизация данных**. Данные пользователей, которые передаются партнеру, должны быть заменены токеном (GUID), который в системе PropDevelopment будет ассоциирован с конкретными данными. Обмен данными с сервисами партнеров должен вестись только с использованием этих токенов.
6. **Шифрование данных**. Передаваемые конфиденциальные данные (фото, токены, данные о помещениях) должны дополнительно шифроваться. Должен быть предусмотрен механизм смены паролей шифрования, когда системы должны уметь расшифровывать данные предыдущим паролем шифрования или уже новым. 
7. **Обмен ключами шифрования**. Обмен ключами шифрования должен быть реализован не через каналы связи с API партнерами. Это должна быть интеграция через сторонний сервис, почту или аппаратный носитель.
